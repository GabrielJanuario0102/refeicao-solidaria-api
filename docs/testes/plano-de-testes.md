## 1. Estratégia

- Na **Sprint 1 (S1)**, verificar rotas públicas da aplicação Web, compilação/testes e endpoint diagnóstico da API, ambiente PostgreSQL/pgAdmin via Docker Compose e **planejar** os cenários de teste dos demais módulos.
- Nas **Sprints 2 a 6 (S2–S6)**, executar os fluxos à medida que forem implementados, registrando pré-condições, massa de dados, passos e evidências verificáveis.
- **Tipos de teste cobertos:** smoke test, funcional (positivo e negativo), regressão, interface responsiva (desktop e mobile), validação de regras de negócio e persistência de dados.
- **Cobertura de domínio:** quatro perfis cadastrados (`DOADOR`, `INSTITUICAO`, `VOLUNTARIO`, `ADMIN`) + acesso público (`Visitante`), além dos módulos de doações, solicitações/recebimento, transporte/logística e administração.
- Para cada execução, informar data, responsável, ambiente, resultado (`PASSOU`, `FALHOU`, `BLOQUEADO` ou `NÃO EXECUTADO`) e evidência (log, commit, PR ou captura).
- **Privacidade e dados de teste:** não utilizar dados pessoais reais desnecessários; cadastros fictícios devem evitar CPFs, CNPJs ou documentos reais.

## 3. Riscos, limitações e observações da Sprint 1

- **Separação entre ambiente demonstrativo Web e persistência da API:** conforme documentado em `docs/requisitos/visao-e-escopo.md`, a primeira versão da aplicação Web utilizará estado/armazenamento local para fluxos demonstrativos em sprints intermediárias, enquanto a API evolui a persistência em PostgreSQL. Os testes não devem presumir integração HTTP/autenticação de produção onde o escopo definir comportamento demonstrativo local.
- **Dependência da Task `REF-15` (Banco de Dados):** até o momento da execução deste smoke test em 19/11/2026, o repositório `refeicao-solidaria-api` contém as entregas integradas de `REF-12` (documentação de visão, escopo, backlog, DoD e guia de contribuição) e `REF-14` (estrutura inicial Spring Boot e endpoint `/api/status`), mas ainda não possui o `docker-compose.yml` nem o documento de modelo conceitual da Task `REF-15`. Por esse motivo, o caso `CT-S1-05` permanece registrado como **BLOQUEADO / NÃO EXECUTADO** até a entrega do responsável.
- **Compatibilidade de JDK no ambiente de teste:** a compilação e os testes da API (`REF-14`) foram validados com `javac [debug parameters release 21]` utilizando JDK 25.0.2 compatível com target Java 21 configurado no `pom.xml`.
